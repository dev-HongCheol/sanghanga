# 테스트 표준 가이드

이 문서는 Gemini가 프로젝트의 테스트 코드를 작성할 때 준수해야 할 표준과 규칙을 정의합니다. 사용자의 학습을 돕고 코드의 신뢰성을 확보하는 것을 목적으로 합니다.

## 🎯 핵심 원칙
1. **격리성 (Test-Only)**: Gemini는 테스트 구현 요청 시 오직 `tests/` 폴더 하위 파일만 수정 가능하며, **어떠한 경우에도 `src/` 하위의 운영 코드를 직접 수정해서는 안 됩니다.** 운영 코드에 문제가 발견되면 사용자에게 보고하고 수정을 제안합니다.
2. **버전 정합성**: 구현 전 반드시 `package.json`을 참조하여 라이브러리(Zod, Vitest, React 등)의 버전을 확인하고, 해당 버전에 최적화된 문법과 API를 사용합니다.
3. **교육적 가치**: 사용자가 테스트 코드를 읽으며 테스트 방법론과 라이브러리 사용법을 학습할 수 있도록 상세한 주석을 제공합니다.
4. **명세 기반 검증**: 반드시 Claude가 작성한 `test-spec.md`의 요구사항과 테스트 케이스를 기반으로 구현합니다.
5. **실시간 업데이트**: 작업 진행 중 `prd.md` 및 `test-spec.md`의 체크리스트를 **실시간으로 업데이트(`- [x]`)**하여 진행 상황을 투명하게 공유합니다.
6. **독립성**: 각 테스트 케이스는 상호 의존성 없이 독립적으로 실행되어야 합니다.

## 🛠 테스트 스택

| 라이브러리 | 역할 및 특징 |
| :--- | :--- |
| **Vitest** | Vite 기반의 초고속 테스트 프레임워크 (Jest 호환) |
| **React Testing Library** | 사용자 관점의 컴포넌트 렌더링 및 인터랙션 검증 |
| **Zustand (Testing)** | 스토어 상태 변경 및 `persist` 로직 검증 |
| **TanStack Query (Testing)** | 서버 데이터 페칭, 캐싱 및 훅 로직 검증 |
| **jsdom** | Node.js 환경에서 브라우저 DOM 시뮬레이션 |
| **user-event** | 마우스 클릭, 키보드 입력 등 정밀한 사용자 동작 재현 |
| **jest-dom** | DOM 상태 확인을 위한 직관적인 Matcher 제공 |
| **v8 coverage** | 코드 검증 범위 측정 및 리포트 생성 |

## 📝 교육용 주석 (Educational Commenting) 규칙
모든 테스트 파일에는 사용자가 학습할 수 있도록 다음 내용의 주석을 반드시 포함합니다.

### 1. 라이브러리 API 설명
생소할 수 있는 라이브러리 함수가 처음 등장할 때 그 역할과 파라미터를 설명합니다.
```typescript
// render: React 컴포넌트를 테스트를 위한 가상 DOM(JSDOM)에 렌더링하는 함수입니다.
// screen: 렌더링된 가상 DOM에서 요소를 찾기 위한 다양한 쿼리 메서드를 제공하는 객체입니다.
import { render, screen } from "@testing-library/react";

// vi: Vitest에서 제공하는 유틸리티로, 함수 모킹(Mocking)이나 시간 제어 등에 사용됩니다.
import { describe, expect, it, vi } from "vitest";
```

### 2. 테스트 구조 설명
`describe`, `it`, `expect` 등 테스트의 기본 구조가 갖는 의미를 설명합니다.
- `describe`: 관련 있는 테스트 케이스들을 하나의 그룹으로 묶습니다.
- `it` (또는 `test`): 개별 테스트 단위이며, "무엇을 테스트하는지" 명확히 기술합니다.
- `expect`: 테스트의 실제 결과가 예상한 값과 일치하는지 검증(Assertion)합니다.

### 3. 모킹(Mocking) 및 가짜 데이터 설명
테스트를 위해 실제 모듈이나 API를 대체하는 '모킹'의 이유와 방법을 설명합니다.

## 📁 파일 및 구조 규칙
- **위치**: 모든 테스트 파일은 프로젝트 루트의 `tests/` 폴더 하위에서 FSD 레이어를 따라 관리합니다.
  - `tests/unit/`: `shared/lib`, `entities/*/model`, `features/*/model` 등 순수 로직/스토어 테스트
  - `tests/integration/`: `app/`, `widgets/`, `features/*/ui` 등 컴포넌트 간 연동 테스트
  - `tests/config/`: 프로젝트 설정 파일(Biome, TS, Tailwind 등) 검증 테스트
- **파일명**: 테스트 대상 파일의 경로를 따르며 `{파일명}.test.ts(x)` 형식을 사용합니다.
- **Setup**: 전역 테스트 설정은 `tests/setup.ts`에서 관리합니다.

## 📊 테스트 실행 명령어

| 명령어 | 용도 | 설명 |
| :--- | :--- | :--- |
| `pnpm test` | 전체 테스트 실행 | 모든 테스트 파일을 한 번 실행하고 종료합니다. |
| `pnpm test:watch` | 테스트 관찰 모드 | 파일 변경을 감지하여 관련 테스트를 자동으로 다시 실행합니다. (개발 환경용) |
| `pnpm test:coverage` | 커버리지 리포트 | 테스트가 소스 코드를 얼마나 검증하는지 측정하고 보고서를 생성합니다. |
| `pnpm exec vitest [경로]` | 특정 파일 테스트 | 특정 폴더나 파일에 대해서만 테스트를 수행하고 싶을 때 사용합니다. |

## 🔍 결과 확인 및 디버깅 가이드

### 1. Vitest 실행 결과 읽기
- **Test Files**: 통과한 테스트 파일의 총 개수입니다.
- **Tests**: 전체 개별 테스트 케이스(`it` 블록)의 통과 및 실패 수입니다.
- **FAIL**: 테스트가 실패한 경우, 실패한 코드 위치와 함께 `Expected`(기대값)와 `Received`(실제 결과값)의 차이를 시각적으로 보여줍니다.

### 2. 커버리지 리포트 해석
- **% Stmts**: 실행된 전체 코드 라인의 비율입니다. (프로젝트 권장: 80% 이상)
- **% Branch**: `if`문이나 삼항 연산자 등의 분기 로직 중 테스트된 비율입니다.
- **Uncovered Line #s**: 테스트가 도달하지 못한 구체적인 코드 라인 번호입니다. 이 부분을 확인하여 테스트 케이스를 보완해야 합니다.

### 3. 디버깅 팁
- **`screen.debug()`**: 컴포넌트 테스트 중 의도한 대로 요소가 찾아지지 않을 때, 이 함수를 호출하면 현재 가상 DOM의 구조를 터미널에 출력하여 확인할 수 있습니다.
- **`vi.fn()` / `vi.spyOn()`**: 외부 함수나 모듈의 호출 여부와 인자 값을 확인하여 로직의 흐름을 추적할 수 있습니다.

## 🔐 외부 API 및 상태 관리 테스트

### 1. Zustand 스토어 테스트
스토어는 순수 함수처럼 테스트하되, `act`를 사용하여 상태 변경을 반영합니다.
```typescript
import { act } from "@testing-library/react";
import { useStore } from "./store";

// 각 테스트 전 스토어 초기화 필수
beforeEach(() => {
  act(() => useStore.getState().reset());
});
```

### 2. TanStack Query 테스트
`QueryClientProvider`로 감싸서 테스트하거나, 커스텀 훅 테스트 유틸리티를 사용합니다.

### 3. 외부 API 모킹 전략
외부 API(키움증권 등)를 사용하는 코드는 다음 전략으로 테스트합니다:
1. **단위 테스트**: 외부 API는 모킹(Mocking)하여 로직만 검증
2. **통합 테스트**: 실제 API 사용 (환경변수 필요, 수동 실행)

## 🚀 테스트 결과 기록 (test-spec.md 업데이트)
테스트 진행 중 및 완료 후 반드시 해당 기능의 `test-spec.md`에 다음을 수행합니다.

1. **실시간 체크**: 개별 테스트 케이스 구현 및 통과 시 즉시 체크박스를 `[x]`로 변경합니다.
2. **결과 요약 기록**: 하단 `테스트 실행 결과` 섹션에 다음 표준 양식으로 기록합니다.

### 표준 결과 기록 양식
```markdown
## 테스트 실행 결과

### 실행 정보
- **날짜**: YYYY-MM-DD
- **담당**: Gemini (Senior Fullstack Developer)
- **도구**: Vitest vX.X.X

### 결과 요약
(pnpm test 실행 결과 텍스트 복사)

### 커버리지 리포트
(pnpm test:coverage 결과 텍스트 복사)
```

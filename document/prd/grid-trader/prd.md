## 🎯 개요

**사용자가 선택한 종목**을 대상으로 **박스권 그리드 트레이딩**을 자동화하여 변동성 수익을 확보하면서 Core 물량(장기 보유)을 유지하는 시스템.

- **라우터**: `/trading-system/grid-trader`
- **예시 시나리오**: HD현대(034020), 현재가 약 30만원, 그리드 간격 5,000~7,000원

## 🔍 기능 요구사항

### 1. 전략 설정

- **종목 검색**: 종목명/코드 자동완성
- **그리드 설정**: 간격(1,000~100,000원), 상단/하단 개수(1~20개), 그리드당 수량
- **자산 배분**: Core(장기 보유) 수량 + Active(트레이딩) 수량
- **최소 보유 한도** (`minHoldingLimit`): 이 수량 이하로 떨어지면 매도 주문 생성 중단
- **목표가** (선택): 설정 시 목표가 미만 매도 불가

**전략 관리**:
- 전략 활성화 시 자동으로 초기 그리드 배치 실행
- 활성 전략 수정 시 자동으로 리밸런싱 (기존 미체결 취소 + 현재가 기준 재배치)

### 2. 그리드 매매 로직

```
↑ 매도 주문 N개 (현재가 + gap, + 2*gap, ...)
━━━━━━ 현재가 ━━━━━━
↓ 매수 주문 N개 (현재가 - gap, - 2*gap, ...)
```

**체결 시 대응**:
- 매수 체결 → 한 칸 위 매도 주문 즉시 생성
- 매도 체결 → 한 칸 아래 매수 주문 즉시 생성

**호가 단위 자동 조정** (중요):
- 모든 주문 가격은 한국 주식시장 호가 단위에 맞춰 자동 조정됨
- 매수: 호가 단위로 내림 (유리한 방향)
- 매도: 호가 단위로 올림 (유리한 방향)
- 그리드 간격은 최대한 유지하되, 호가 단위 배수로 조정됨

**제약 조건**:
- **매도 가능 수량**: `총 보유 수량 - minHoldingLimit` (예: 3주 보유, 2주 Core → 1주만 매도 가능)
- `보유 수량 ≤ minHoldingLimit` → 매도 주문 생성 중단
- 예수금 부족 → 매수 주문 생성 방지
- 그리드 이탈 → 리밸런싱 트리거

### 3. 시스템 스케줄링

#### 일일 스케줄

| 시간 | 작업 |
|:-----|:-----|
| 08:00 | OAuth 2.0 토큰 갱신 |
| 08:30 | 잔고 확인, 기존 미체결 주문 조회 |
| 08:50 | 활성 전략 초기 그리드 배치 |
| 09:00~15:30 | 체결 이벤트 Polling (1초 간격) |
| 15:30 | 미체결 취소 + 일일 P&L 기록 |
| 매시간 | 리밸런싱 체크 |

#### 실시간 데이터 동기화 (v1.4)

**서버 측 Cron Jobs**:

| Cron | 키움 API | 주기 | 실행 조건 | 용도 |
|:-----|:---------|:-----|:---------|:-----|
| 가격 동기화 | ka10001 (주식기본정보) | 1초 | **장중만** (평일 09:00~18:00) | 활성 전략의 종목 현재가 조회 → 메모리 캐시 + SSE push |
| 잔고 동기화 | kt00018 (계좌평가잔고내역) | 3초 | 항상 (ENABLE_CRON=true) | 계좌 잔고/보유 수량 조회 → 메모리 캐시 + SSE push |
| 체결 감지 | ka10075/ka10076 | 2초 | **장중만** (평일 09:00~18:00) | 체결 이벤트 감지 → DB 저장 + 카운터 주문 생성 |
| 리밸런싱 체크 | - | 10분 | **장중만** (평일 09:00~18:00) | 그리드 이탈 감지 → 자동 리밸런싱 실행 |

**장시간 제어** (로컬 시간 기준):
- 평일 09:00~18:00 (정규장 + 시간외 거래)
- 정규장: 09:00~15:30
- 시간외 종가: 15:40~16:00
- 시간외 단일가: 16:00~18:00
- 잔고 동기화는 장시간 체크 없이 항상 실행
- 공휴일은 현재 미지원 (요일만 체크)

**클라이언트 통신**:
- ~~PollingRefresher (제거)~~: 1초마다 전체 페이지 리패칭 (비효율)
- **SSE 구독** (신규): 서버가 데이터 변경 시 즉시 push (폴링 불필요)
- **Zustand Store**: SSEProvider가 단일 연결 생성 → 전역 Store 업데이트 → 각 컴포넌트 구독

**키움 API 호출량** (활성 그리드 N개):
- 초당 N + 0.83회 (가격 N회 + 잔고 0.33회 + 체결 0.5회)
- 예: 그리드 2개 → 초당 2.83회 (사용자 수와 무관하게 고정)

### 4. 리밸런싱

**트리거**: 10분 주기 자동 체크 / 가격 그리드 범위 이탈 / 수동 버튼

**그리드 이탈 조건** (v1.5):
- 현재가 > 최상단 그리드 가격 (모든 매도 주문 위로)
- 현재가 < 최하단 그리드 가격 (모든 매수 주문 아래로)

**로직**: 미체결 전체 취소 → 현재가 기준 그리드 재계산 → 신규 주문 생성

### 5. 서버 재시작 동기화

**자동 복구 메커니즘** (v1.5):
- 10분마다 실행되는 리밸런싱 체크가 자동으로 서버 재시작을 감지
- **활성 전략인데 미체결 주문이 없으면** → 자동으로 그리드 배치 실행
- 서버 장애로 9시에 주문이 안 걸렸더라도, 재구동 후 10분 이내에 자동 배치됨

**동작 시나리오**:
1. 09:00 시스템 오류 발생 (그리드 배치 실패)
2. 11:00 서버 재구동
3. 11:00~11:10 사이 리밸런싱 체크 Cron 실행
4. 활성 전략 감지 → 미체결 주문 0개 → 자동 그리드 배치 ✅

## 🏗️ 기술 스택

| 항목 | 결정 사항 |
|:-----|:---------|
| **DB** | Supabase Self-Hosting (PostgreSQL) — `@supabase/supabase-js` |
| **스키마** | `database/schemas/grid-trader/` (실행 완료) |
| **Cron** | `node-cron` (서버 측 주기적 작업) |
| **실시간 통신** | Server-Sent Events (SSE) — Next.js Route Handler |
| **메모리 캐시** | `Map<string, T>` (서버: 현재가, 잔고) |
| **상태 관리** | Zustand (클라이언트: SSE 데이터 → 전역 Store) |
| **체결 감지** | Polling 방식 (키움 WebSocket은 시세 전용, 체결은 REST만 가능) |
| **알림** | 텔레그램 Bot API (Phase 2) |

### 아키텍처

#### 전체 구조

```
Frontend (Next.js) ↔ Server Actions ↔ 키움 REST API
                   ↔ SSE             ↔ Supabase (PostgreSQL)
```

#### 실시간 데이터 동기화 흐름 (v1.4)

```
[서버]
Cron (1~3초) → 키움 API 조회
                    ↓
               메모리 캐시 (Map)
                    ↓
               SSE push to clients
                    ↓
               DB 저장 (주문/체결만)

[클라이언트]
SSEProvider (단일 연결)
       ↓
EventSource 구독
       ↓
Zustand Store (price-store, balance-store)
       ↓
각 컴포넌트 구독 (폴링 없음, 자동 리렌더링)
```

**데이터별 저장 전략**:
- **메모리 캐시**: 현재가, 잔고 (휘발성, 최신값만 필요)
- **DB 저장**: 전략 설정, 주문 내역, 체결 이벤트 (영속성 필요)

**키움 API 목록** (상세 명세: `document/api/`):
- `ka10001` 주식기본정보 (현재가)
- `ka10075` 미체결요청
- `ka10076` 체결요청
- `kt10000` 주식 매수주문
- `kt10001` 주식 매도주문
- `kt10002` 주식 정정주문
- `kt10003` 주식 취소주문
- `kt00018` 계좌평가잔고내역요청

### Rate Limiting
- 전체: 초당 20회 / 주문: 초당 5회 이하
- 초기 그리드 배치: 500ms 간격 분산

## 🚨 리스크 및 주의사항

- **Core 물량 보호**: `minHoldingLimit` 이하 매도 금지는 코드 레벨에서 강제
- **예수금 부족**: 매수 주문 전 반드시 잔고 확인
- **계좌 비밀번호**: `.env.local` 환경변수로만 관리
- **호가 단위**: 모든 주문 가격이 자동으로 호가 단위에 맞춰 조정됨 (키움증권 API 제약)
- **그리드 간격**: 설정한 간격과 실제 간격이 호가 단위로 인해 미세하게 다를 수 있음
- **실전 운영 전**: 모의투자 계좌로 충분히 테스트

# Grid Trader 통합 테스트 명세

> 작성일: 2026-05-08 | 대상: Phase 1 핵심 기능

## 개요

Grid Trader의 주요 플로우(전략 생성 → 그리드 배치 → 체결 → 리밸런싱)에 대한 통합 테스트 명세.

## 테스트 시나리오

### 1. 전략 생성 및 초기 그리드 배치

**플로우**:
```
사용자 입력 → createStrategyAction → DB 저장 → deployGridAction
→ 현재가 조회 → 계좌 잔고 조회 → 그리드 계산 → 주문 배치 (API + DB)
```

**테스트 케이스**:
- ✅ 정상 시나리오
  - 입력: HD현대(034020), 그리드 간격 5000원, 상단 3개, 하단 3개, 그리드당 수량 1주
  - 예수금: 충분 (100만원)
  - 보유 수량: 5주 (Core 2주, Active 3주)
  - 예상 결과:
    - 매수 주문 3개 배치 (예수금 차감)
    - 매도 주문 1개만 배치 (매도 가능 수량 = 5 - 2 = 3주, 그리드당 1주씩 총 3개 가능하나 상단 3개 중 현재가에 가까운 1개만)
    - DB: 4개 주문 PENDING 상태로 저장

- ❌ 예수금 부족
  - 예수금: 10만원 (매수 1개만 가능)
  - 예상 결과: 매수 주문 1개만 배치, 로그 경고

- ❌ 보유 수량 부족
  - 보유 수량: 2주 (Core 2주)
  - 매도 가능 수량 = 0
  - 예상 결과: 매도 주문 0개, 로그 경고

**검증**:
- DB `sh_grid_strategies` 테이블에 전략 생성 확인
- DB `sh_grid_orders` 테이블에 주문 저장 확인 (status: PENDING)
- 키움 API 호출 횟수 확인 (매수 N회 + 매도 M회)

---

### 2. 체결 감지 및 대응 주문 생성

**플로우**:
```
pollFills (1초 주기) → 키움 API 체결 조회 → DB PENDING 비교
→ 신규 체결 감지 → handleFillEvent → 대응 주문 생성
```

**테스트 케이스**:
- ✅ 매수 체결 → 한 칸 위 매도 주문 생성
  - 초기 상태: 매수 주문 PENDING (가격 295,000원, 수량 1주)
  - 키움 API: 해당 주문 체결 (체결가 295,000원)
  - 예상 결과:
    - DB: 기존 주문 상태 PENDING → FILLED
    - DB: `sh_fill_events` 테이블에 체결 이벤트 저장
    - 키움 API: 매도 주문 생성 (가격 300,000원, 수량 1주)
    - DB: 새 매도 주문 PENDING 상태로 저장

- ✅ 매도 체결 → 한 칸 아래 매수 주문 생성
  - 초기 상태: 매도 주문 PENDING (가격 305,000원, 수량 1주)
  - 키움 API: 해당 주문 체결 (체결가 305,000원)
  - 예상 결과:
    - DB: 기존 주문 FILLED
    - 키움 API: 매수 주문 생성 (가격 300,000원, 수량 1주)
    - DB: 새 매수 주문 PENDING

- ❌ 매수 체결 but 보유 수량 ≤ Core 물량 → 매도 주문 생성 안 함
  - 체결 후 보유 수량: 2주 (= Core 물량)
  - 예상 결과: 대응 주문 생성 안 함, 로그 경고

**검증**:
- `sh_grid_orders` 상태 변화 확인
- `sh_fill_events` 저장 확인
- 대응 주문 가격이 호가 단위에 맞는지 확인

### 3. 키움 앱 수동 취소 → DB 자동 동기화

**플로우**:
```
사용자가 키움 앱에서 주문 취소 → pollFills
→ 키움 API 미체결 조회 → DB PENDING 비교 → 불일치 감지 → DB 동기화
```

**테스트 케이스**:
- ✅ 키움 앱에서 주문 1개 취소
  - 초기 상태: DB PENDING 주문 3개 (A, B, C)
  - 키움 앱: B 주문 취소
  - pollFills 실행 후:
    - 키움 API 미체결: [A, C]
    - DB PENDING: [A, B, C]
    - 불일치: B
  - 예상 결과:
    - DB: B 주문 상태 PENDING → CANCELLED
    - 로그: "취소된 주문 감지 (키움 앱에서 수동 취소) { count: 1, orderIds: [B] }"

**검증**:
- DB `sh_grid_orders` 테이블에서 B 주문 상태 확인
- 로그 메시지 확인

---

### 4. 수동 리밸런싱

**플로우**:
```
사용자 버튼 클릭 → rebalanceGridAction
→ 미체결 주문 전체 취소 (API + DB) → 현재가 조회 → deployGrid
```

**테스트 케이스**:
- ✅ 정상 리밸런싱
  - 초기 상태: 미체결 주문 5개, 현재가 300,000원 → 310,000원으로 상승
  - 리밸런싱 실행:
    - 기존 주문 5개 취소 (키움 API + DB)
    - 현재가 310,000원 기준으로 신규 그리드 계산
    - 신규 주문 배치
  - 예상 결과:
    - 기존 주문 5개 → CANCELLED
    - 신규 주문 N개 → PENDING
    - 토스트 알림: "취소: 5건 | 신규 배치: N건"

- ❌ 비활성 전략 → 리밸런싱 거부
  - 전략 상태: `is_active: false`
  - 예상 결과: 에러 메시지 "활성 상태인 전략만 리밸런싱할 수 있습니다"

**검증**:
- DB 주문 상태 변화 확인
- 키움 API 호출 횟수 확인 (취소 5회 + 신규 배치 N회)
- UI 토스트 알림 메시지 확인

---

### 5. 목표가 설정 시 매도 제한

**플로우**:
```
deployGrid 또는 handleFillEvent → 매도 주문 생성 시
→ 가격 < 목표가 체크 → 조건 미달 시 주문 생성 스킵
```

**테스트 케이스**:
- ✅ 목표가 미만 매도 주문 생략
  - 전략 설정: 목표가 350,000원
  - 현재가: 300,000원
  - 그리드 매도 가격: 305,000원, 310,000원, 315,000원
  - 예상 결과:
    - 모든 매도 주문 생략 (350,000원 미만)
    - 로그: "목표가 미만 매도 주문 생략 { price: 305000, targetPrice: 350000 }"

- ✅ 목표가 이상 매도 주문 생성
  - 그리드 매도 가격: 355,000원
  - 예상 결과: 매도 주문 생성

**검증**:
- DB `sh_grid_orders` 테이블에 목표가 미만 주문이 없는지 확인
- 로그 메시지 확인
